# Milestones 0 and 1: report

## What shipped

**M0, scaffolding.** A workspace with six crates (published as `fernet-fs-*`,
see DECISIONS 1). Lints: `clippy::pedantic`, `unwrap`/`expect`/`panic` and
missing docs all deny. `rustfmt`, `cargo deny`, and a pinned toolchain with a
separately checked MSRV (1.85). CI on GitHub Actions: fmt, clippy, test, docs,
msrv, deny, a 60-second fuzz smoke run per target, and macOS build plus unit
tests. Stubs for README, GRAMMAR, FORMAT and DECISIONS.

**M1, read the depths.**
- `fernet-fs-path`: the full grammar. Every time-spec form, both lenses, RFC 6901
  tokens plus an extension for keys no filesystem can name. Parsing is total and
  printing is its exact inverse. Zero dependencies.
- `fernet-fs-formats`: span-tracking JSON (hand-written, JSONC-tolerant), TOML
  (`toml_edit`) and YAML (`saphyr-parser` events), read-only, plus a driver
  registry with extension-first detection.
- `fernet-fs-core`: the resolver for real paths and `#` lenses, built on a
  per-component `lookup` that the mount will share. Includes a bounded tree cache.
- `fernet` CLI: `cat` and `ls`, house-style errors, and the brief's exit codes.

## Deviations from the brief

- `TimeSpec::Relative { amount, unit }` instead of `Relative(Duration)`, so specs
  print back exactly (DECISIONS 8).
- `ScalarType::Datetime`, plus `Node::key_span` and `Node::text`, on top of the
  trait in 4.3 (DECISIONS 11).
- The tree cache landed in M1 rather than with the mount (DECISIONS 17).
- No `arbitrary`-based structured fuzz target. The proptest generators cover
  structured paths (DECISIONS 21).

## What I learned

- The bijective grammar is what makes "real names win" exact. Any normalisation
  in the parser would make some real file unreachable.
- `toml_edit` spans are exact, but a TOML table isn't a single range in the file.
  `Edit::Remove` on tables needs a list of ranges in M4.
- `saphyr-parser` markers count characters, not bytes, and scalar spans include
  `&anchor`/`!tag` properties. Both are handled in the driver and covered by tests
  with non-ASCII input.
- Golden comparisons need a format-aware notion of equality. Rendered text is
  "as written" for numbers (`0x1F`), so the test interprets each rendered value
  with the reference parser instead of comparing strings.
