# Milestone 6 (v1.0), frozen ice: report

## What shipped

- **FORMAT.md, stable**: format version 1, with a compatibility promise
  (later versions read `fernet-store 1`; incompatible changes need a new
  `FORMAT` line).
- **An independent reader**, `tools/format-reader/` (172 lines). It was written
  from FORMAT.md alone and uses only `blake3`, `crc32c` and `zstd`. It lists
  every version and can dump their bytes.
- **The v1 fixture store**, committed at `tests/fixtures/store-v1`. It has
  writes, a rename, a delete, a removed mark, a live mark, and repeated
  content, plus a plain-text `expected.txt`.
- **Benchmarks** as ignored tests (`crates/fernet/tests/bench.rs`), run in
  release mode by a CI job.
- **Native-speed reads through the mount**: kernel passthrough where
  available, the kernel page cache with automatic invalidation otherwise.
- **A release workflow** for Linux x86_64 and aarch64 and macOS aarch64,
  including completions and checksums.
- **A user guide** under `docs/guide/`, and README updates.

## Acceptance criteria

| Criterion | Evidence |
| --- | --- |
| FORMAT.md complete and stable | `docs/FORMAT.md` |
| An independent reader recovers every version in a test store | `tools/format-reader/tests/fixture.rs` |
| Every later version reads v1 stores; fixture committed | `tests/tests/fixture_store.rs` (current store code) and the reader test |
| `cat` of a real file through the mount within 10% of the backing fs | `bench.rs::cat_through_the_mount_is_within_10_percent`: **0.91–1.03x with passthrough** (this machine, kernel 6.18). Without passthrough, 1.15–1.20x via `std::fs::read`, which **misses the target** (DECISIONS 49) |
| `#` read of a key in a 1 MiB JSON under 5 ms warm | `bench.rs::hash_read_in_a_1mib_json_is_under_5ms`: **20 µs** |
| Release binaries for Linux (x86_64, aarch64) and macOS (aarch64) | `.github/workflows/release.yml`; triggered manually to check the builds; no release published |

## Not done, or not verifiable here

- **macOS mount verified by hand with FUSE-T** (an M3 item): there's no Mac in
  this environment. CI builds and unit-tests on macOS; `docs/MACOS.md` has the
  steps and a checklist.
- **The 10% benchmark without passthrough.** GitHub's shared runners use
  kernels older than 6.9, so CI measures the page-cache path. The job reports
  rather than gates.
- **Publishing 1.0** (pushing a `v1.0.0` tag) is left to the maintainer.
- Open questions from brief §8, still open: FSKit (Q2), `x-fernet-type` (Q3),
  time ranges (Q4).
