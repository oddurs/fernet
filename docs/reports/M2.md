# Milestone 2 (v0.2), snowfall: report

## What shipped

- **`fernet-fs-store`**: segments with headers, CRC-checked records, zstd blobs
  addressed by BLAKE3, an atomically replaced manifest, the writer lock, group
  commit, torn-tail recovery on open, segment rolling, and a read-only `verify`.
  The index is `redb` for the lock holder and an in-memory replay for readers;
  both answer through the same query code.
- **Time**: every spec form resolves with `jiff` in the user's zone: relative,
  named days (most recent past, a week back on the same weekday), absolute with
  or without offsets, counts, `first`, marks and listings. DST gaps and folds use
  the "compatible" rule.
- **`@` in `fernet-fs-core`**: past files, past directories, tombstones, version
  listings (with `.N` for same-second collisions and an entry per mark), `#` on
  past files, and real names winning in history too. A file with history but
  nothing early enough gets the brief's message: `no version of notes.md before …
  (first kept: …)`.
- **Capture**: `snapshot` (deduplicated: identical bytes record nothing),
  `snapshot_tree` (with tombstones for vanished files), `.fernetignore` plus the
  default ignores and the 50 MiB limit, and `fernet watch`.
- **CLI**: `init`, `log` (with `--size`), `core`, `mark`/`--rm`, `diff`,
  `verify`, `reindex`, `watch`, plus history-aware `cat` and `ls`.
- **Docs**: FORMAT.md is a complete draft of format version 1. GRAMMAR.md covers
  time lenses on directories and the listing names. DECISIONS 22–29.

## Acceptance criteria

| Criterion | Evidence |
| --- | --- |
| Truncating the active segment at every byte offset of the last record opens, verifies, and loses exactly that record | `crates/fernet-store/tests/store.rs::crash_at_every_byte_of_the_last_record` |
| Flipping any byte in a sealed segment is reported by verify | `…::every_byte_flip_in_a_sealed_segment_is_reported` (every byte of a 4-record segment), plus `record::tests::every_bit_flip_is_detected` |
| Delete index + reindex gives identical results (invariant 5) | `…::reindex_gives_identical_answers`: a proptest over random writes, deletes, renames, marks and unmarks, comparing reopened, reindexed and in-memory answers for random query instants |
| Fixed clock + `America/New_York` + DST resolves every spec form | `tests/tests/history.rs::every_spec_form_across_dst` (18 forms around the 2026-03-08 boundary) and `fernet-core` `time::tests` |
| 40 identical saves store one blob | `…::identical_saves_store_one_blob` (store) and `history.rs::identical_saves_are_one_version` (through snapshots) |

Also: a watcher end-to-end test (`crates/fernet/tests/cli.rs::watch_captures_outside_changes`),
a `segment_scan` fuzz target (6.9 M runs per minute, clean), and CI green on
Linux and macOS.

## Deviations

- MSRV 1.90 instead of 1.85, because `redb` 4 requires it (DECISIONS 22).
- Readers that can't get the lock use an in-memory index (DECISIONS 23). The
  brief only describes the persistent one.
- `@~N` and the `@` listing match nothing on directories (DECISIONS 25).
- `config.toml` is read with a line scan (DECISIONS 27).

## What I learned

- `redb`'s exclusive file lock shaped the reader design. Splitting the index
  behind a trait made the invariant-5 test stronger, because it now compares
  three independently built indexes.
- Treating a crc failure on a record that ends exactly at EOF as a torn write
  is necessary (ext4 can leave zeroed tails), and it's safe because sealed
  segments never get that allowance.
- jiff's `Date::to_zoned` and `DateTime::to_zoned` already implement the right
  DST semantics. The tests pin them so a library change can't move them
  silently.
