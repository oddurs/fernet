# Milestones 3 (v0.3) and 4 (v0.4): report

## What shipped

**M3, the mount, read-only.** `fernet-fs-fuse` maps every kernel lookup to
`Fernet::lookup`, the same step the CLI folds over, and holds an inode table
keyed by resolved identity. Real files pass through; past files and values are
rendered at open. `fernet mount` unmounts on SIGINT/SIGTERM, notices outside
unmounts, and has `--daemon`. `docs/MACOS.md` covers FUSE-T and macFUSE.

**M4, write back.**
- Splices in all three drivers: type-preserving `SetScalar` (JSON, TOML, YAML),
  `Insert`/`Remove` for JSON (style-matching byte splices) and TOML
  (`toml_edit`). YAML anchors, aliases and block scalars stay read-only.
- Core writes: per-file lock, temp file, fsync, a changed-on-disk check with one
  retry (`EAGAIN`), rename, snapshot. `fernet write`.
- A writable mount (now the default): passthrough writes, create, mkdir, unlink,
  rename, symlink and setattr on real files. Buffered `#` values are applied on
  flush, `mkdir`/`rm`/new names work inside files, and everything under `@` is
  `EROFS`.
- Capture while mounted: one trailing-edge debouncer per path, fed by the
  mount and by a `notify` watcher for outside changes. Editors' temp files are
  ignored.
- Compaction: a pure plan plus a crash-safe rewrite. `fernet compact
  [--dry-run]`.

## Deviations

- The mount is writable by default from v0.4 (`--read-only` for v0.3
  behaviour), and it's the store's writer (DECISIONS 39).
- A refused `#` write surfaces on `flush`/`fsync`/`close`. Shells ignore close
  errors on redirections, so `echo nope > n#/port` exits 0 but changes nothing
  (DECISIONS 39).
- JSON integers and floats are interchangeable; TOML and YAML are strict
  (DECISIONS 36).
- `fernet` gained a default `mount` feature so it builds without libfuse on
  macOS (CI checks both).

## Bugs found by the new tests

- `snapshot_tree` stamped each file separately, so `src@first` showed half a
  tree (fixed: a tree capture is one moment, DECISIONS 34).
- The foreground mount held the stderr lock, so the first log line from a FUSE
  thread deadlocked it (DECISIONS 41).
- Renames rekeyed inodes with `join("")`, giving paths a trailing slash and
  `ENOTDIR` on the renamed file.
- Shells' `dup2` + close flushed an empty `#` buffer before the write arrived.

## What I learned

- Writing through FUSE is mostly about when to apply: `flush` happens per fd
  close, `release` once, and shells close a duplicate before writing. Applying
  on the first flush that follows a write (and on release otherwise) is the rule
  that works for `echo`, `printf`, editors and `cp`.
- A single debouncer for every source of change (mount, watcher, renames) makes
  "one version per save" fall out naturally for every editor tried. No
  editor-specific logic was needed beyond ignoring their temp names.
- Writing compaction as a pure `plan` plus a step-wise rewrite made the crash
  test cheap: every step boundary is a test case.
